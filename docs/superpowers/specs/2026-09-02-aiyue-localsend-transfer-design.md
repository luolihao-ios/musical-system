# 爱乐互传 LocalSend 风格传输重构设计

## 目标

将爱乐互传的 Windows 与 iOS 客户端重构为 LocalSend 风格的局域网传输工具：自动发现附近设备、刷新设备列表、传输前确认、支持任意文件，并为音乐提供歌曲包增强能力。首要且必须达成的互通目标是爱乐互传自己的 Windows 与 iOS；只有在不增加明显复杂度和维护成本时，才增加对官方 LocalSend 的兼容。

## 界面与交互

- 主界面分为“接收”“发送”“设置”三个入口。
- 发送页提供文件、文件夹、文本、剪贴板入口和“刷新附近设备”按钮。
- 附近设备以卡片显示设备名、设备类型和状态；不显示手动地址、公钥输入框。
- 点击设备后展示待发送内容并发起准备请求；接收端必须明确接受或拒绝。
- 接收页显示待处理请求、文件清单、总大小、验证码和传输进度。
- 设置页只提供设备名称、接收目录、开机启动、网络发现开关和版本信息。

## 协议与发现

- 采用 LocalSend Protocol v2 的设备信息结构、UDP 组播发现和 HTTP 注册回退。
- 默认使用 UDP 224.0.0.167:53317 发现，TCP 53317 提供 REST API；端口可在设置中修改。
- 实现 `/api/localsend/v2/register`、`/prepare-upload`、`/upload`、`/cancel` 及反向下载所需接口。
- 保留 HTTPS/证书指纹与 SHA-256 校验；设备指纹用于排除自身并记录已知设备。
- 不再要求用户复制公钥或手动填写地址；发现失败时只显示网络诊断提示。

## 音乐增强

- 发送音乐时可选择“打包为歌曲包”。歌曲包使用 `.aiyuepack` 扩展名，本质为 ZIP。
- 包含 `manifest.json`、音频文件、歌词文件和封面文件；manifest 保存标题、艺术家、专辑、格式、时长及文件校验值。
- 接收端识别歌曲包后先展示歌曲信息，用户确认后解包到接收目录，并通过现有音乐导入接口导入播放器。
- 普通音乐文件和任意非音乐文件继续按 LocalSend 普通文件传输，不强制打包。

## 错误处理与安全

- 每次传输都必须由接收端确认；拒绝、超时、取消和校验失败均显示明确原因。
- 文件写入使用安全相对路径和临时文件，完成校验后再原子移动到目标目录。
- 发现不可用时提示检查本地网络权限、防火墙和 AP 隔离，不回退到公网服务。
- 参考 LocalSend 源码时保留 Apache-2.0 许可和版权声明，不复制其 UI 资源。

## 分阶段验证

1. 协议向量和发现数据结构测试。
2. Windows 与 iOS 的自动发现、准备、确认、上传、取消和校验测试。
3. 任意文件、文件夹、文本、剪贴板传输测试。
4. `.aiyuepack` 打包、解包、错误包拒绝和音乐导入测试。
5. Windows 安装包、桌面图标、默认路径和防火墙提示验证。
