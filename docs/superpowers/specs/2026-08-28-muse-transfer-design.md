# 暮色互传：Windows 与 iOS 局域网传输工具设计

日期：2026-08-28

## 目标

在现有“暮色音乐”生态旁新增独立应用“暮色互传”，用于 Windows 与 iOS 设备在同一局域网内互传任意文件。应用不依赖账号、云存储或互联网中继；对于音频、同名歌词、封面和歌单提供自动识别、归组及一键导入“暮色音乐”的增强体验。

首版只要求暮色互传的 Windows 与 iOS 客户端彼此互通，不兼容 LocalSend 协议。每一批传输都必须由接收端明确确认，不提供可信设备自动接收。

## 产品与平台边界

仓库新增两个独立原生应用和一份跨端协议规范：

```text
transfer-windows/
transfer-ios/
docs/transfer-protocol/
```

- Windows 使用 C#、WPF 和 .NET 10，支持 Windows 10/11 x64。
- iOS 使用 Swift、SwiftUI，最低支持 iOS 17。
- 两端共享协议定义、测试向量和产品视觉语言，不共享运行时代码。
- 暮色互传不读取或修改暮色音乐数据库，不承担播放功能。
- 与暮色音乐的协作只通过受控的系统应用链接和文件交接入口完成。
- 首版只支持同一局域网内直连，不实现账号、云中继、互联网穿透或长期后台服务器。
- iOS 仅在前台或系统授予的有限后台时间内传输；应用被系统完全挂起后不承诺持续接收。

## 总体架构

两端均包含五个职责清晰的模块。

### 设备发现

使用 Bonjour/mDNS 广播和发现设备。广播只包含随机设备 ID、用户可见名称、平台、协议版本和临时服务端口，不包含文件名、音乐库或传输历史。

同时提供局域网地址手动连接，以便在 mDNS 被路由器或系统策略阻断时继续使用。设备 ID 在重新安装后变化，用户可以在设置中手动重置。

### 会话安全

应用启动后使用临时身份提供传输服务。发送请求先提交不可变文件清单；接收端生成短时会话和六位验证码，在两端显示相同验证码。只有用户确认设备、清单、保存位置和验证码后，接收端才签发限时传输令牌。

令牌绑定发送设备、接收设备、文件清单和会话期限，不能用于另一批文件。应用退出或会话超时后旧授权失效，重试必须再次由接收端确认。

### 传输引擎

传输使用自定义 JSON 控制协议和 HTTP/TCP 流式数据承载。接收端广播当前短期 P-256 公钥，发送端为每批传输生成新的 P-256 临时密钥；双方通过 ECDH 和 HKDF-SHA256 派生本批会话密钥。清单、文件名、目录结构、控制结果和文件分块均使用 AES-GCM 加密认证。六位验证码由会话密钥与清单摘要派生，用户核对并确认后才允许上传。大文件按最多 1 MiB 分块，不整体载入内存。

TCP/HTTP 不提供安全边界。每个加密消息使用唯一的 96 位 nonce 和绑定会话、文件、分块位置及清单摘要的关联数据。应用只使用 .NET 与 CryptoKit 的系统密码学实现，不内置共享证书私钥，也不要求 iOS 生成 X.509 服务器证书。

引擎支持：

- 单文件、多文件和带子目录的文件夹；
- 总体与单文件进度、实时速度和预计剩余时间；
- 发送端或接收端取消；
- 已校验分块基础上的中断续传；
- 每文件大小与 SHA-256 完整性校验；
- 并发会话、文件数量、清单大小和请求频率限制。

### 文件管理

接收端在传输前展示目标目录和可用空间。文件先写入临时目录，完整校验成功后再原子移动到最终位置。未完成内容不得以成功文件名出现在最终目录。

相对路径必须规范化。应用拒绝绝对路径、根路径、`..`、设备路径和其他可能逃逸目标目录的名称。重名默认追加序号生成副本，不覆盖原文件；设置中可以改为逐个询问，但首版不支持静默覆盖。

Windows 允许选择保存目录和打开文件所在位置。iOS 先保存在应用管理区域，完成后允许通过系统分享或“文件”App 导出。

### 音乐增强

发送清单生成时识别支持的音频、LRC、常见封面图片和歌单文件，并按文件名、目录及歌单引用关系归为音乐包。归组只增加清单元数据，不改变用户原有文件结构。

完成后，普通文件提供打开、定位或分享操作；音乐包额外提供“导入暮色音乐”。LRC、封面和歌单只在用户触发导入后交给播放器，不静默修改音乐库。

## 传输协议流程

协议按以下顺序执行：

1. **发现**：接收端发布服务，发送端解析设备能力和协议版本。
2. **清单提议**：发送端提交文件相对路径、大小、类型、目录关系和音乐归组摘要。
3. **人工确认**：接收端显示发送设备、文件数量、总大小、最大单文件、音乐摘要、目标目录、剩余空间和六位验证码。
4. **会话授权**：用户接受后，接收端签发绑定当前清单的短时令牌；拒绝时立即销毁会话，不接收文件数据。
5. **分块上传**：发送端按文件和块索引上传，接收端落入临时目录并记录已经校验的块。
6. **完成校验**：接收端核对文件大小和 SHA-256，校验成功后移动到最终位置。
7. **结果确认**：双方记录每个文件的成功、失败或取消结果；音乐内容显示导入入口。

协议版本必须明确协商。重大不兼容变更提升主版本并拒绝传输；兼容能力通过能力字段协商，未知字段由旧客户端忽略。

## 核心交互

### 首页与发送

首页包含附近设备、发送队列和最近接收。设备卡显示设备名称、平台和在线状态。点击设备后选择文件或文件夹；Windows 额外支持拖放，iOS 支持“文件”选择器和系统分享面板发送到暮色互传。

发送端完成扫描后展示文件数量、总大小和音乐识别结果，用户确认后才向目标设备提交清单。传输任务展示总体进度、当前文件、速度、剩余时间和取消入口。

### 接收确认

接收端每批都弹出确认界面，明确显示：

- 发送设备和平台；
- 六位验证码；
- 文件数量、总大小及最大单文件；
- 文件与音乐内容摘要；
- 保存位置及剩余空间；
- 接受、拒绝和更换保存位置操作。

未知文件类型可以正常接收。空间不足、目标目录无权限、清单非法、请求过期或大小超过限制时不得进入上传阶段，并提供可执行的修复提示。

### 历史与设置

历史只保存设备名、时间、文件名、大小、结果和本地位置，不保存文件内容、验证码、令牌或会话密钥。用户可以删除单条记录或清空全部历史。

设置提供设备名称、默认保存位置、重名策略、接收大小限制、设备 ID 重置和历史清理。首版不提供自动接受或后台常驻开关。

## 暮色音乐交接

### Windows

暮色互传将用户选中的音乐包通过暮色音乐注册的应用协议或受控启动参数交接。参数只传递清单文件或受限本地路径，播放器负责重新验证路径、复制或索引文件并返回导入结果。播放器未安装时保留文件并提供打开保存位置。

### iOS

两款应用采用同一开发者签名下的 App Group 共享容器，并通过自定义 URL Scheme 唤起暮色音乐。暮色互传将用户明确选择的音乐包复制到共享交接目录，写入带版本的导入清单后再唤起播放器。播放器完成或拒绝导入后清理交接内容。播放器未安装时允许保存到“文件”App。

交接协议必须记录导入状态并具备幂等标识，避免用户重复点击造成重复导入。播放器数据库结构不属于互传协议的一部分。

## 界面设计

界面延续暮色音乐的暗色唱片室风格，使用独立的传输标识、深灰背景、暖红强调色、设备光晕和大尺寸进度环，不使用 LocalSend 的名称、图标、文案或素材。

Windows 使用桌面三栏布局：左侧导航，中间附近设备与任务列表，右侧任务详情。iOS 使用“传输、历史、设置”底部导航，发送选择和接收确认使用系统 Sheet。

两端均支持系统深浅色、高对比度、键盘或辅助功能导航及减少动态效果。关键状态不能只通过颜色表达。

## 异常与恢复

- **设备离线**：保留任务清单，设备重新出现后允许用户发起重试。
- **网络中断**：保留已经校验的分块；重新建立会话并由接收端再次确认后，从有效分块继续。
- **应用退出**：下次启动恢复可重试记录，但不恢复授权或密钥。
- **校验失败**：不生成最终文件，保留有效临时分块并允许重传损坏部分。
- **发送端取消**：接收端停止写入并标记任务取消，按保留期限清理临时数据。
- **空间不足**：上传前阻止接受；传输中空间变化导致失败时保留可恢复状态并允许更换位置。
- **iOS 进入后台**：申请有限后台执行时间；系统暂停后显示等待重新打开，回到前台再恢复。
- **恶意请求**：路径非法、清单变化、令牌过期、块索引越界或频率超限时立即终止会话。

临时文件设置明确保留期限，并在成功、用户删除历史或期限到达后清理。日志不记录文件内容、会话密钥、验证码或完整敏感路径。

## 测试策略

### 跨端协议测试

在 `docs/transfer-protocol/` 保存不含真实隐私数据的固定测试向量，覆盖清单规范化、密钥派生、令牌绑定、分块索引、续传位图和 SHA-256。C# 与 Swift 必须对同一输入得到一致结果。

### 单元测试

两端覆盖：

- 设备发现状态与协议版本筛选；
- 接收确认、拒绝和会话过期；
- 路径规范化及目录穿越拒绝；
- 重名副本策略；
- 分块状态、取消和续传计算；
- 文件校验和临时文件提交；
- 音频、歌词、封面和歌单归组；
- 历史记录清理和敏感字段排除。

### 集成与真机测试

- Windows 本机使用双实例完成发现、确认、发送、拒绝、取消和续传测试。
- Windows 自动测试、Release 发布和安装包在当前环境验证。
- iOS 通过 GitHub macOS runner 编译并运行 XCTest。
- Windows 与 iPhone 在真实 Wi-Fi 网络完成跨端发现和互传。
- 验证 mDNS 不可用时的手动地址连接。
- 验证 iOS 前后台切换、系统分享入口和暮色音乐交接。

## 首版验收标准

1. Windows 与 iOS 能在同一局域网发现彼此，也能通过局域网地址手动连接。
2. 可以发送任意单文件、多文件和带子目录的文件夹。
3. 接收端每一批都必须明确确认；拒绝后不得上传任何文件数据。
4. 两端显示准确的单文件与总体进度、速度、结果，并支持取消和中断续传。
5. 接收文件保持目录结构；重名时默认不覆盖；校验失败不产生伪成功文件。
6. 音频、同名歌词、封面和歌单自动归组，完成后可以由用户交给暮色音乐导入。
7. Windows 可在当前环境完成构建、测试、发布和安装包验证。
8. iOS 可由 GitHub macOS runner 构建和测试，并通过真机完成最终跨端验收。
9. 应用不需要账号、互联网服务或云存储，断开互联网后仍可完整使用。
10. 路径穿越、过期令牌、清单篡改、空间不足、网络中断和应用后台暂停都有明确且可恢复的处理。

## 不在首版范围

- 与 LocalSend 或其他第三方客户端互通；
- 互联网远程传输、NAT 穿透或云中继；
- 账号、跨设备历史同步或可信设备自动接收；
- 剪贴板同步、纯文字消息或聊天；
- 音频转码、在线元数据、封面或歌词下载；
- iOS 被系统完全挂起后的长期后台接收；
- 静默覆盖已有文件或静默修改暮色音乐资料库。
