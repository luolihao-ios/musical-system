# iOS 播放状态统一与播放器交互改进设计

日期：2026-08-28

## 目标

修复音乐库点击歌曲无法可靠切歌、音频与歌词状态串歌的问题，并统一音乐库、搜索结果、专辑、歌手、文件夹、歌单和播放队列的选歌行为。在同一轮改动中完善歌词跳转、播放页布局、音乐库信息展示、Mini Player 和播放队列管理。

最低系统版本保持 iOS 17，应用继续只播放用户本地导入或系统音乐资料库中的歌曲，不增加联网下载能力。

## 已确认的根因

音乐库通过 `loadQueue(_:startIndex:)` 后再调用 `play()`。`loadQueue` 当前会优先使用持久化的 `lastTrackID`，因此上一首歌曲仍存在于新队列时，会覆盖用户刚点击的 `startIndex`。播放队列弹窗直接调用 `playQueueItem(at:)`，不会经过这段恢复逻辑，所以队列可以切歌而主页不能。

分类详情页点击歌曲时也会通过 `LibraryModel.filteredTracks` 重建队列，而不是使用当前专辑、歌手或文件夹的歌曲集合，因此页面显示列表和实际播放队列可能不一致。

歌词目前由 `NowPlayingModel` 根据播放状态加载，但歌词结果没有携带 Track ID，也没有任务取消或结果校验机制。当前读取虽是本地同步读取，状态边界仍不足以防止切歌过程中的旧内容残留，并且未来改为异步读取时会产生竞态风险。

## 架构方案

### 唯一播放状态源

`PlaybackController` 继续作为全 App 唯一播放状态源。页面模型不得维护独立的 `currentSong` 或 `currentTrack`。

新增统一的主动选歌入口：

```swift
func playTrack(_ track: TrackSnapshot, in queue: [TrackSnapshot]) async throws
```

音乐库全部歌曲、搜索结果、专辑、歌手、文件夹、歌单和播放队列最终都调用该入口。播放队列内部按索引选择时，也先解析出目标 Track，再进入同一套切歌流程。

播放记录恢复只用于 App 初始化后的首次恢复，不参与用户主动点击歌曲。用户选择始终优先于 `lastTrackID`。

### 原子切歌流程

每次主动切歌生成新的播放代次标识。切换流程按以下顺序执行：

1. 验证目标歌曲可用，并规范化候选队列。
2. 使上一轮尚未完成的加载失效。
3. 暂停旧资源，将新队列、当前索引、当前 Track ID、位置零值和初始 duration 写入全局状态。
4. 加载目标音频资源。
5. 加载结束后验证播放代次和 Track ID；过期结果直接丢弃。
6. 写入真实 duration、从零 seek 并开始播放。
7. 保存当前歌曲和播放位置，系统锁屏信息通过同一状态观察链更新。

如果音频加载失败，目标歌曲仍作为当前选择显示，但播放状态保持暂停，并由现有错误通道报告错误；不得回退播放上一首却显示新歌曲信息。

### 歌词与 Track ID 绑定

切歌状态一到达 `NowPlayingModel`，立即执行：

- 清空上一首歌词、当前歌词索引和临时选择状态；
- 取消上一首歌词加载任务；
- 以目标 Track ID 启动歌词读取和解析；
- 结果返回时同时验证任务未取消且 `loadedTrackID == currentTrack.id`；
- 校验失败的旧结果直接丢弃。

无歌词、读取失败或解析结果为空时显示唱片/光影的无歌词状态，不保留上一首的任何歌词文本。

## 组件和交互设计

### 音乐库与分类页面

`LibraryModel.play` 接收目标歌曲和当前页面可见队列。不同入口传入各自上下文：

- 全部歌曲：全部歌曲或当前搜索结果；
- 专辑、歌手、文件夹：当前分组的歌曲；
- 最近播放：当前最近播放列表；
- 歌单：当前歌单歌曲；
- 播放队列：当前队列。

歌曲行显示 metadata 中的标题、歌手和专辑。只有 metadata 标题为空时才使用文件名；fallback 文件名按最后一个连字符尝试拆分为“歌曲名 - 歌手”，无法可靠拆分时保留原文件名。

音乐库入口卡显示分组数量，例如“专辑 5”“歌手 8”“文件夹 3”。进入分组后才显示“12 首歌曲”。最近播放继续显示歌曲数量。

当前歌曲行使用主题强调色，并显示播放中或暂停状态图标。标记依据全局 `PlaybackState.currentTrack.id`，不依赖页面局部状态。

### 黑胶与歌词主视图

播放页主区域只有两种互斥模式：唱片模式和歌词模式。默认显示大黑胶唱片；点击唱片切换到大歌词视图，点击歌词区域的非歌词操作位置可切回唱片。两种模式通过轻量淡入和缩放动画切换，并尊重“减少动态效果”。

无歌词时保留大唱片及现有光影/图标提示，不显示空白歌词页。

音量 Slider 和同一行的扬声器图标全部删除。播放模式按钮移入核心控制区，并保留上一首、播放暂停、下一首和播放队列入口。

### 歌词浏览与跳转

歌词行可点击。点击某句后：

1. 将该句设为临时选中项；
2. 使用歌词 timestamp 调用统一播放器 `seek(to:)`；
3. 播放进度和系统播放状态立即同步；
4. 如果歌曲原本正在播放则继续播放；如果原本暂停则保持暂停；
5. 恢复当前时间驱动的歌词高亮和自动跟随。

用户拖动歌词时进入手动浏览状态，自动滚动暂停。拖动结束后保留用户浏览位置短暂时间；用户点击歌词后立即恢复自动跟随，未点击则在约两秒无交互后恢复。切歌会立即结束旧歌曲的手动浏览状态。

### Mini Player

Mini Player 顶部细进度条保留。除播放暂停和下一首按钮的独立点击区域外，其余整条区域均可进入完整播放页。实现上避免嵌套 Button，确保控制按钮不会同时触发打开播放页。

### 播放队列

队列直接读取和修改 `PlaybackController.state.queue`，不保存独立当前歌曲状态。支持：

- 当前歌曲强调标记；
- 点击歌曲通过统一选歌入口切换；
- 拖动调整顺序，同时根据 Track ID 修正当前索引，保证当前音频不变；
- 删除非当前歌曲，仅更新队列和索引；
- 删除当前歌曲，立即播放删除位置之后的下一首；若删除的是末尾歌曲则播放新队列中的第一首；
- 清空队列时暂停并卸载当前资源，清空 currentTrack、position、duration 和播放状态。

所有队列修改都更新持久化播放信息。队列为空时系统锁屏播放信息也清空。

## 数据一致性规则

任意时刻，以下界面和播放数据必须属于同一个 Track ID：

- 音频资源；
- `PlaybackState.currentTrack`；
- 标题、歌手、专辑和封面；
- 歌词内容及当前歌词索引；
- position 和 duration；
- 系统锁屏/控制中心信息；
- 队列当前歌曲标记。

异步结果只能在其播放代次和 Track ID 均与当前状态一致时提交。切歌失败、任务取消和快速连续点击都不得让旧结果覆盖新状态。

## 测试策略

实施采用测试驱动方式，先补充失败测试，再修改实现。

核心单元测试包括：

- 用户主动选择不被持久化 `lastTrackID` 覆盖；
- 主页、搜索、分类、歌单和队列传入正确的上下文队列；
- 快速连续 A → B 切换只允许 B 的加载结果提交；
- 切歌立即清空旧歌词，过期歌词结果不会覆盖当前歌曲；
- 点击歌词 timestamp 正确调用 seek；
- 队列重排保持当前 Track ID，索引正确更新；
- 删除当前歌曲播放下一首，删除末尾后循环到第一首；
- 删除最后一首或清空队列会停止并清空状态；
- metadata 缺失时的文件名拆分和保底显示；
- 分类入口显示分组数量而非歌曲数量。

完成后运行项目现有的 iOS 测试与 `ios-app/scripts/verify.sh`。由于本机为 Windows，最终 Xcode 编译和真机验证仍由 GitHub macOS 构建执行；无需持续等待构建，由用户提供结果后再处理平台特有问题。

## 不在本次范围

- 联网搜索或下载歌曲、歌词和封面；
- 改变最低 iOS 17 要求；
- Apple Music 在线流媒体；
- 均衡器、音效或音频格式转码；
- Windows WPF 版本的对应改动。

## 品牌名称与应用图标

手机桌面显示名改为“爱乐之城”。Swift target 名、可执行文件名和 Bundle ID `com.luolihao.musicalsystem` 保持不变，避免影响现有构建、签名和测试配置。音乐资料库权限说明中的旧名称同步替换为“爱乐之城”。

应用图标使用 1024×1024 方形母图：深酒红到黑色渐变背景，中央为带柔和高光的黑胶唱片，唱片中心融入简洁的金红色音符或声波。图标不包含文字、水印和细碎装饰，主体保留足够安全边距，确保 iOS 圆角裁切和小尺寸显示仍然清晰。生成结果写入现有 `AppIcon.appiconset/AppIcon-1024.png`，不修改资产目录名称。
