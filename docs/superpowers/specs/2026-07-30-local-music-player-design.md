# 本地音乐播放器设计

## 目标

构建一款 Flutter 跨平台本地音乐播放器，输出 Windows 桌面应用和 iOS 原生安装包。应用只扫描、导入和播放用户设备上的音乐，不接入在线曲库、搜索、下载或上传功能。

界面采用原创的暗色唱片室风格：深色背景、暖红强调色、圆角封面卡片与半透明层次。整体具有沉浸式音乐播放器体验，但不使用网易云音乐的名称、商标、图标、文案或素材。

## 平台和技术边界

- Flutter 统一实现界面、业务状态和本地数据。
- Windows 支持用户添加多个本地音乐文件夹并递归扫描。
- iOS 支持两种来源：读取获用户授权的系统音乐资料库，以及通过“文件”App 导入音频文件。
- iOS 系统资料库仅显示及播放系统允许本应用访问的条目；从“文件”导入的文件复制进应用沙盒，由应用管理。
- 全部歌曲元数据、歌单和偏好保存于设备本地，不访问网络服务。

## 信息架构和界面

采用自适应布局。

- 宽屏 Windows：左侧导航、内容列表、固定底部迷你播放器。
- iPhone：底部导航、内容区和底部迷你播放器。
- 导航入口包括本地音乐、专辑、歌手、文件夹、最近播放、我喜欢和自建歌单。
- 点击迷你播放器进入沉浸式播放页，显示封面、歌曲信息、进度、播放控制、歌词和播放队列。

## 音乐库和本地数据

统一歌曲模型保存：唯一标识、标题、歌手、专辑、时长、文件/媒体库引用、封面、来源、导入日期和最后播放时间。

本地数据库保存：

- 喜欢状态；
- 自建歌单及曲目顺序；
- 播放历史；
- 扫描目录和索引状态；
- 播放偏好（音量、播放模式、最后播放位置）。

“我喜欢”是内置歌单，不可删除。自建歌单可创建、重命名、添加或移除曲目并删除。

## 播放与歌词

播放层负责：播放/暂停、上一首/下一首、进度拖动、音量、顺序循环、单曲循环、随机播放及播放队列。Windows 和 iOS 都支持后台播放、锁屏媒体控制和耳机控制。

Windows 扫描时查找与音频同名的 `.lrc` 文件；导入流程也会关联可用的本地歌词。播放页解析时间轴并逐行滚动、高亮当前歌词。没有歌词或歌词解析失败时，显示旋转唱片、封面呼吸光效与频谱感动态效果。

## 异常处理

- 没有扫描目录或没有歌曲时，展示导入/扫描引导。
- 文件丢失、格式不支持或解码失败时，标记歌曲不可播放并提供明确提示，不中断其他曲目。
- iOS 权限被拒绝时，保留“文件导入”可用，并引导用户前往系统设置授权。
- 歌词缺失或损坏时，静默切换到无歌词动效。
- 重启后恢复本地库、歌单、喜欢状态、历史与播放偏好；不强制自动续播。

## 构建、测试与发布

- Windows：输出可安装或可直接运行的桌面包。
- iOS 测试：GitHub Actions 在 macOS 构建机生成测试产物；用户通过爱思助手签名后装入个人 iPhone 验证。项目不配置开发证书、Ad Hoc 设备清单或 TestFlight。
- iOS 发布：测试通过后，使用 Apple 发布签名构建，通过 App Store Connect 提交审核。
- GitHub 中已有的密钥保持为现有配置；实施阶段仅在确有需要时定义所需名称和用途，不输出私钥或证书内容。

## 验收标准

1. Windows 能扫描用户选择的本地文件夹，iOS 能读取授权资料库和导入文件。
2. 无网络时可完整浏览、搜索、播放和管理本地音乐。
3. 所有基础播放控制、队列和播放模式正确工作，并支持后台/锁屏媒体控制。
4. `.lrc` 歌词按时间滚动；无歌词时播放页显示稳定的动态视觉。
5. 喜欢与自建歌单的增删和重启后持久化正确。
6. 缺失文件、不可支持格式、缺少权限及损坏歌词均有明确且可恢复的处理。
