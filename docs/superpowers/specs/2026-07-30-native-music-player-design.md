# 双原生本地音乐播放器设计

## 目标

将现有 Flutter 双端方案调整为两个完全独立的原生应用：

- iOS 使用 Swift、SwiftUI 和 SwiftData，最低支持 iOS 17。
- Windows 使用 C#、WPF、MVVM 和 SQLite，支持 Windows 10/11 x64。

两个应用保持一致的产品定位和视觉语言，但不共享代码、数据库或用户数据。应用只扫描、导入和播放设备中的本地音乐，不接入在线曲库，不搜索、下载或上传网络音乐。

界面采用原创的暗色唱片室风格：黑灰背景、暖红强调色、圆角封面、柔和光晕和唱片动效。整体体验可借鉴主流沉浸式音乐播放器的信息层级，但不使用网易云音乐的名称、商标、图标、文案或素材。

## 仓库结构

仓库最终采用以下结构：

```text
musical-system/
├─ ios-app/
├─ windows-app/
├─ .github/workflows/
└─ docs/
```

### iOS 项目

`ios-app/` 包含独立的 SwiftUI 应用、Xcode 项目定义、资源、测试和 iOS 构建配置。

主要技术：

- Swift 和 SwiftUI；
- SwiftData；
- AVFoundation 和 AVAudioSession；
- MediaPlayer；
- XCTest。

### Windows 项目

`windows-app/` 包含独立的 WPF 解决方案、应用源码、测试、发布配置和 Inno Setup 安装脚本。

主要技术：

- C# 和 WPF；
- .NET 10；
- MVVM；
- Microsoft.Data.Sqlite；
- NAudio；
- TagLibSharp；
- xUnit；
- Inno Setup。

### Flutter 代码退出方式

迁移期间现有 Flutter 代码暂时保留，用于核对已经实现的交互和测试场景。只有当 iOS 与 Windows 原生项目都能完成各自的基础构建后，才从当前工作树移除 Flutter 工程。历史版本继续保存在 Git 中，可以随时恢复。

## 平台与数据边界

- 两端的音乐索引、收藏、歌单、播放历史和设置分别保存在当前设备。
- 不实现账号、云同步或跨设备数据迁移。
- 两端使用相同的概念模型，但不要求数据库结构或内部标识一致。
- iOS 最低支持 iOS 17。
- Windows 首发支持 Windows 10/11 x64。

## 核心功能

两端均提供：

- 本地音乐库；
- 按标题、歌手和专辑搜索；
- 专辑、歌手、文件夹和最近播放入口；
- 收藏与内置“我喜欢”歌单；
- 自建歌单的创建、重命名、删除、添加歌曲、移除歌曲和排序；
- 播放队列；
- 播放、暂停、上一首、下一首、进度拖动和音量；
- 顺序循环、单曲循环和随机播放；
- 后台播放、锁屏信息、耳机按键和系统媒体控制；
- 同名 `.lrc` 歌词关联、时间轴解析、自动滚动和当前行高亮；
- 无歌词时的旋转唱片、封面光晕和频谱感动画。

## Windows 应用设计

### 音乐来源与索引

用户可以添加一个或多个本地音乐文件夹。应用递归扫描文件夹，但不复制或移动原音乐文件。

支持格式：

- MP3；
- M4A/AAC；
- FLAC；
- WAV；
- OGG Vorbis。

TagLibSharp 读取标题、歌手、专辑、时长和内嵌封面。扫描器同时查找与音频文件同名的 `.lrc` 文件。

SQLite 保存：

- 音乐文件路径及稳定标识；
- 元数据和封面缓存引用；
- 扫描目录；
- 收藏状态；
- 自建歌单及歌曲顺序；
- 播放历史；
- 音量、播放模式和上次播放位置等设置。

扫描过程采用增量更新。文件被移动或删除时保留索引并标记为不可播放；重新扫描发现文件后恢复条目，避免直接丢失歌单关系。

### 播放

NAudio 管理音频输出、播放进度、音量、队列和播放模式。

- MP3、M4A/AAC、FLAC 和 WAV 使用 Windows Media Foundation 能力解码。
- OGG 使用项目内的轻量 Vorbis 解码组件。
- 无法创建解码器时将歌曲标记为不可播放，并继续处理队列中的下一首。

系统媒体控制通过项目依赖中的 Windows API 合约接入，不要求开发电脑安装独立 Windows SDK。

### 界面

Windows 使用适合桌面管理的高密度布局：

- 左侧固定导航；
- 中部音乐库、专辑、歌手、文件夹和歌单内容；
- 顶部搜索和筛选；
- 底部固定迷你播放器；
- 点击迷你播放器进入沉浸式播放页；
- 播放页展示封面或唱片、歌曲信息、歌词、进度、控制按钮和队列。

### 本地构建与安装

Windows 开发以本机流程为主：

1. 本地还原项目依赖；
2. 本地编译和运行 WPF 应用；
3. 本地运行全部 Windows 测试；
4. 本地生成 Windows x64 自包含 Release；
5. 本地使用 Inno Setup 生成安装包。

当前电脑已有 .NET 10 SDK 和 Windows Desktop Runtime，不需要安装 Windows SDK。实施时仅补充体积较小的 Inno Setup，并优先安装到 E 盘。

安装包要求：

- 仅当前用户安装；
- 不请求管理员权限；
- 允许用户选择安装目录；
- 创建开始菜单入口；
- 可选创建桌面快捷方式；
- 提供标准卸载项；
- 自包含 .NET 运行时，目标电脑不用另装 .NET。

GitHub Windows 工作流用于自动测试、验证构建和提供备用安装包，不替代本地发布能力。

## iOS 应用设计

### 音乐来源

iOS 支持两个独立入口：

1. 读取获得用户授权的系统音乐资料库；
2. 从“文件”App 导入音频和歌词。

系统音乐资料库只纳入本应用有权读取且能取得本地可播放地址的条目。云端未下载、受保护或无法取得播放地址的条目不进入本地索引。

从“文件”导入的音频复制进应用沙盒，由应用管理。用户可以一次选择音频和同名 `.lrc` 文件，导入器自动建立关联。重名文件根据来源和内容生成唯一标识，不直接覆盖已有文件。

支持格式：

- MP3；
- M4A/AAC；
- FLAC；
- WAV；
- AIFF。

iOS 原生版不支持 OGG，以避免引入额外的大型解码库。

### 数据

SwiftData 保存：

- 音乐条目和沙盒文件引用；
- 系统音乐资料库引用；
- 收藏；
- 自建歌单及歌曲顺序；
- 播放历史；
- 播放设置。

“我喜欢”是内置歌单，不可删除。自建歌单支持创建、重命名、删除、添加歌曲、移除歌曲和排序。

### 播放与系统集成

- AVFoundation 负责本地文件播放；
- AVAudioSession 使用后台音频类别；
- MPNowPlayingInfoCenter 更新锁屏标题、歌手、封面和进度；
- MPRemoteCommandCenter 接收锁屏、耳机和控制中心指令；
- App 开启后台音频能力；
- 播放器不强制在重启后自动播放。

### 界面

iOS 使用符合单手操作的底部导航和沉浸式播放页：

- 底部导航进入音乐库、歌单和设置；
- 迷你播放器固定在底部导航上方；
- 播放页以大尺寸唱片或封面为视觉中心；
- 歌词、进度和播放控制位于拇指易触区域；
- 无歌词时唱片持续旋转，并显示柔和呼吸光与频谱感动画。

## 歌词

歌词解析器支持：

- 标准 LRC 时间标签；
- 一行多个时间标签；
- 两位或三位毫秒精度；
- 忽略无法识别的元信息；
- 按时间排序；
- 根据播放位置计算当前歌词行。

歌词缺失、为空或解析失败时，不中断播放，直接切换到无歌词动画。

## 异常处理

### 通用

- 单个文件损坏不阻断整个扫描或队列。
- 播放失败时显示明确提示，并允许重试、定位文件或从索引移除。
- 数据库写入失败时不伪装成功，保留可恢复的错误信息。
- 应用日志不记录音乐文件内容、Apple 凭据或签名材料。

### Windows

- 文件丢失：标记不可播放，重新扫描后尝试恢复。
- 文件夹无权访问：保留已有索引并提示重新授权或移除文件夹。
- 解码失败：跳过当前歌曲，继续队列。
- 安装或升级：保留用户数据库和缓存目录。

### iOS

- 音乐资料库权限被拒绝：文件导入继续可用，并提供前往系统设置的入口。
- 系统音乐条目没有本地可播放地址：不导入该条目。
- 文件导入中断：清理未完成的临时副本，不影响已经导入的音乐。
- 沙盒文件丢失：保留歌单关系并标记条目不可播放。

## 验收标准

1. 仓库包含相互独立的 `ios-app/` 和 `windows-app/`。
2. Windows 能在当前电脑本地编译、运行、测试、发布和生成无需管理员权限的安装包。
3. Windows 安装包允许选择安装目录，安装后有开始菜单入口和标准卸载项。
4. iOS 能通过 GitHub macOS 工作流生成可供爱思签名的未签名 IPA。
5. Windows 能扫描用户选择的本地音乐文件夹；iOS 能读取授权资料库并从“文件”导入音乐。
6. 无网络时可完成浏览、搜索、播放、收藏、歌单和历史管理。
7. 播放控制、队列、播放模式、后台音频和系统媒体控制正确工作。
8. `.lrc` 歌词按时间滚动；无歌词时显示稳定的唱片动画。
9. 两端数据完全独立，重启后收藏、歌单、历史和设置仍然存在。
10. 文件丢失、格式不支持、权限不足和歌词损坏均有明确、可恢复的处理。
