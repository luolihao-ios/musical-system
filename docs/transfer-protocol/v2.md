# 爱乐互传协议 v2

## 传输与编码

TCP/HTTP 只承担局域网字节流承载，不提供安全边界。控制 JSON、路径和文件分块都必须先封装为 AES-GCM 密文。属性采用 lowerCamelCase；接收端忽略未知属性，但拒绝 `protocolVersion` 不为 `2` 的请求。单个文件分块最多 1 MiB，可以在内存中完成一次认证加解密，但不得缓冲完整文件。

清单摘要是规范 JSON 的 SHA-256 小写十六进制值。规范 JSON 固定按 `protocolVersion`、`senderId`、`items`、`musicGroups` 排列；项目按清单顺序输出，项目属性依次为 `id`、`relativePath`、`size`、`sha256`，音乐组属性依次为 `id`、`itemIds`。

## 服务发现

服务类型为 `_musetransfer._tcp.local`。TXT 记录包含 `id`、`name`、`platform`、`v=2`、接收端 X9.63 未压缩 P-256 公钥 `pk` 和公钥 SHA-256 指纹 `kid`，不得包含文件或历史信息。客户端也可以通过局域网主机和端口手动连接，但必须另行输入或扫描接收端公钥。

## 密钥协商与加密信封

接收端为应用运行期生成短期 P-256 密钥，发送端为每批传输生成新的 P-256 密钥。双方通过 ECDH 得到原始共享秘密，令 `salt = SHA256(receiverPublic || senderPublic)`，再通过 HKDF-SHA256 和 UTF-8 info `muse-transfer-v2` 派生 32 字节会话密钥。

敏感消息使用 AES-256-GCM、随机且不重复的 12 字节 nonce 和 16 字节 tag。提议关联数据为 `proposal|v2`；文件块关联数据为 UTF-8 `sessionId|fileId|chunkIndex|offset|total|manifestDigest`。接收端必须先验证 tag，再解析 JSON或写入临时文件。

六位验证码取 `HMAC-SHA256(sessionKey, manifestDigest)` 前四字节的小端无符号整数对 `1,000,000` 取模并补足六位。用户确认同时验证设备身份、密钥交换结果和清单。

## 端点

| 方法与路径 | 用途 | 成功状态 |
|---|---|---|
| `POST /v2/sessions` | 提交发送端公钥和加密清单信封 | `202 Accepted` |
| `PUT /v2/sessions/{id}/files/{fileId}/chunks/{index}` | 上传一个加密文件块 | `204 No Content` |
| `POST /v2/sessions/{id}/complete` | 请求校验并提交全部文件 | `200 OK` |
| `GET /v2/sessions/{id}` | 凭提议密钥查询加密状态、上传令牌与已确认分块 | `200 OK` |

创建会话返回 256 位随机 `proposalKey`。状态查询必须通过 `X-Muse-Proposal-Key` 提交该值；只有状态转为 `accepted` 后才返回短时上传令牌。文件上传与完成请求使用 `X-Muse-Session-Token` 和 `X-Muse-Manifest-Digest`。文件块请求携带标准 `Content-Range: bytes start-end/total`，偏移、长度和总大小必须与清单一致。

## 状态

状态为 `pending`、`accepted`、`rejected`、`transferring`、`completed`、`failed` 或 `cancelled`。允许的转换为：

- `pending → accepted | rejected | cancelled`
- `accepted → transferring | cancelled | failed`
- `transferring → completed | cancelled | failed`

终态不可再次转换。重连可以读取已确认块，但必须建立新会话并再次人工确认。

## 授权与限制

接受时签发的令牌绑定会话 ID、发送设备 ID、双方公钥指纹、清单摘要、过期时间和随机 nonce。默认有效期五分钟，应用重启立即失效。提议密钥和状态响应也通过会话密钥保护。

默认限制为单批 10,000 个文件、清单 JSON 8 MiB、最多两个并行文件流；接收端可以配置更低的总大小限制。清单、路径、块索引、令牌或摘要不合法时，必须在写入最终目录前拒绝。

## 错误

错误响应使用：

```json
{"code":"session_not_accepted","message":"The receiver has not accepted this session."}
```

`code` 供程序判断，`message` 仅供当前界面显示。协议定义的错误包括 `invalid_manifest`、`unsupported_version`、`session_not_found`、`session_not_accepted`、`session_expired`、`invalid_token`、`unsafe_path`、`invalid_range`、`limit_exceeded`、`hash_mismatch` 和 `insufficient_storage`。
