## 功能清单

### 1. 导入、扫描与音乐资料

- 从“文件”一次导入多首音乐，以及同名 LRC 歌词和封面文件。
- 从已授权的文件夹扫描本地音频；用户主动触发扫描，避免启动时重复扫描。
- 授权读取设备音乐资料库中具有本地资源地址的歌曲；云端或受保护、没有本地地址的项目不会导入。
- 支持爱乐互传交接链接与 `.aiyuepack` 音乐包。导入前校验交接清单、路径和 SHA-256，已处理的交接编号不会重复导入。
- iOS 支持 MP3、M4A、AAC、FLAC、WAV、AIF、AIFF；不支持 OGG。
- 读取内嵌标题、歌手、专辑、时长和封面；元数据缺失时按文件名解析标题和歌手。
- 按内容指纹识别同一音频，重复导入不会形成重复歌曲记录。
- 保留随文件带入的封面和同名歌词。没有封面时，基于歌曲稳定标识、标题和歌手生成不透明 JPEG 程序化封面。

### 2. 新增的在线资料补全

- 导入歌曲时，如果同名 LRC、内嵌歌词或已有歌词均不存在，会按标题、歌手、专辑、时长检索同步歌词；已有歌词不会被覆盖。
- 导入歌曲时，如果没有内嵌封面、伴随封面或已有封面，会检索封面；检索无结果时保留程序化封面。
- 候选歌曲须通过标题、歌手和时长校验；信息不充分时会采用更严格的唯一性判断，避免把明显不相干的资料写入本地。
- 当前资料源包括 LRCLIB、iTunes、MusicBrainz/Cover Art Archive，并保留网易云接口作为回退来源。结果会保存到本地应用支持目录，之后离线可用。
- 查询失败不会阻止音频导入或本地播放。请求之间约有 1.1 秒节流，单次请求有超时与大小限制。
- 该功能不是本机 AI 识别，也不会根据音频内容生成歌词；它依赖歌曲已有的文字元数据和在线资料匹配。

### 3. 新增的开放许可在线音乐

- 音乐库右上角提供在线搜索入口，可按歌曲、歌手或歌词关键词搜索。
- 搜索结果显示来源和许可信息，支持有试听地址的曲目试听。
- 仅“公共领域”或 Creative Commons 许可的曲目显示下载操作；许可证未知的结果不可下载。
- 当前目录包含 Internet Archive 的开放音乐、Jamendo，以及只提供元数据而未确认许可的第三方结果；下载后导入本地资料库。
- 在线目录不可用时显示空结果，不能影响本地音乐库、已下载歌曲和离线播放。

### 4. 音乐库与管理

- 搜索歌曲、歌手或专辑。
- 按专辑、歌手、文件夹浏览，查看最近播放。
- “收藏”独立为底部标签页，点击心形可收藏或取消收藏；收藏列表可直接播放。
- 删除歌曲会从资料库和播放队列移除。
- 自建歌单支持创建、改名、删除、从资料库添加歌曲、移除歌曲和拖动排序。
- 歌曲行显示当前播放状态、封面、标题和歌手。

### 5. 播放、歌词与队列

- 点击任意歌曲、收藏歌曲、歌单歌曲或队列歌曲即可开始播放，并生成对应播放队列。
- 支持播放、暂停、上一首、下一首、进度拖动、音量、列表循环、单曲循环和随机播放。
- 播放队列支持点选切歌、排序、删除和清空。
- 支持后台播放、锁屏控制和耳机媒体按键；离开应用时保存当前歌曲、进度、音量和播放模式。
- 有 LRC 歌词时按播放进度高亮并自动滚动；用户滑动歌词后暂时停止自动跟随，约两秒后恢复；点击歌词可跳转到对应时间。
- 详情页展示大尺寸封面；点击封面可查看歌词，歌词页可回到同一张封面。没有歌词时显示唱片和光影效果。
- 播放中的封面在原有静态声波位置叠加动态声波，暂停时停止波动。

### 6. 新增的底部播放器手势

- 歌曲开始播放后显示贴合屏幕底部的小播放器，提供打开详情、播放/暂停、下一首和关闭。
- 小播放器和播放详情共用同一个底部面板。拖动时高度按手指的全局移动距离实时变化。
- 向上拖动后松手会展开为播放详情页；展开过程不会再弹出第二个页面。
- 向下拖动后，若位移超过触摸开始时面板高度的三分之一，松手关闭播放器；较短拖动会回弹。
- 面板测量、拖动事件和状态切换会记录在文件诊断日志中，用于真机问题定位。

### 7. 稳定性、隐私与诊断

## App Store Connect 上传前构建号检查清单

只有准备上传到 App Store Connect/TestFlight 的构建，才需要执行以下构建号检查；本地调试、模拟器测试以及不上传的普通构建，不需要为了每次构建都递增构建号：

1. 在 `ios-app/project.yml` 中递增 `CURRENT_PROJECT_VERSION`，构建号必须大于 App Store Connect 中该 Bundle ID 最近一次成功上传的构建号。
2. 同一个构建号一旦成功上传，即使只是重新上传或重新执行上传工作流，也不能再次使用；必须先递增后再构建。未上传的本地构建可以继续使用当前构建号。
3. `MARKETING_VERSION`（例如 `0.2`）和 `CURRENT_PROJECT_VERSION`（例如 `36`）是两个不同字段；本次上传版本应记录为 `0.2 (36)`。
4. 提交并推送包含新构建号的代码后，再从该提交启动 GitHub Actions；不要使用旧提交或旧 IPA 重试上传。仅做本地验证时无需修改构建号。
5. GitHub Actions 的运行编号只用于定位工作流，不能替代 App 的构建号。

如果 App Store Connect 返回“bundle version must be higher than previously uploaded version”，说明上传前的构建号已经被使用，应该递增 `CURRENT_PROJECT_VERSION`、更新本文件中的版本记录，再重新构建上传。
