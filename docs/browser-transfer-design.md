# 电脑浏览器传文件

## 目标

iPhone 提供“电脑传文件”入口。电脑与手机连接同一局域网后，通过 Chrome/Edge 打开手机显示的 HTTP 地址，无需安装 Windows 客户端即可上传、浏览、下载文件和创建文件夹。现有客户端传输继续使用原有服务。

## 用户流程

进入入口时启动独立网页服务，优先使用 8080；端口不可用时选择可用端口，只在监听就绪后显示实际 Wi-Fi IPv4 地址和端口。无 Wi-Fi 地址时明确提示连接网络。提供复制地址和关闭服务操作。

手机保持页面在前台时可用。退出页面或进入后台关闭网页服务，清理未完成上传；返回前台后重新启动并刷新地址。不要宣称 iOS 可无限后台监听。

网页采用爱乐互传现有紫色风格，提供目录面包屑、文件名、大小、文件夹入口、下载按钮、上传按钮、拖拽区域及新建文件夹。传输结果留在网页，失败可重新选择并重试。

开启时生成会话访问码，电脑输入后才能访问文件。会话只在本次开启期间有效。继承现有接收确认规则：每批上传显示名称、数量、总大小，手机接受后才发送正文。网页在等待期间显示等待手机确认。

## 服务器与存储

使用独立 Network.framework 服务及独立串行队列；不要在现有客户端 HTTP 解析器内叠加网页路由。网页资源随 App 打包，不依赖外网 CDN。

上传正文分块写入临时文件，校验声明大小、写入成功后移入目标目录；下载分块读取并发送。不能将整个视频加载到 Data。连接中断、取消、超时、空间不足时关闭文件和连接并清理临时文件，保留原有文件。

所有格式保存到 App Documents 下的“爱乐互传”，不写相册。网页与客户端共用该接收目录；排除内部“待发送”暂存目录。所有路径由服务器限定在共享根目录内，拒绝父目录跳转、绝对路径及符号链接越界。遇到同名文件自动追加序号，不覆盖用户文件。

## HTTP 接口

- GET /：返回 HTML/CSS/JavaScript 页面。
- POST /web/session：验证本次访问码，建立会话。
- GET /web/files?path=：返回当前目录的文件名、相对路径、类型、大小。
- POST /web/folders：在指定目录创建文件夹。
- POST /web/uploads：提交文件清单并请求手机确认，返回上传批次标识。
- GET /web/uploads/{id}：查询等待、接受、拒绝、取消、失败或完成状态。
- PUT /web/uploads/{id}/{fileId}：按清单上传原始文件正文。
- DELETE /web/uploads/{id}：取消该批次并清理临时文件。
- GET /web/download?path=：下载指定文件，正确编码中文文件名并强制附件下载。

上传和下载接口校验会话。修改接口校验来源；不开放跨域访问。文件名在网页中按文本显示，不能插入 HTML。响应带准确 Content-Length、Content-Type 和 HTTP 状态，不暴露 App 沙箱绝对路径。

## 进度与诊断

网页上传展示各文件已发送字节、等待保存、完成或失败；只有服务器确认落盘后标为完成。总进度按实际字节汇总。浏览器下载由系统下载管理器显示进度。

日志继续写入 App 文件目录，记录服务启动/停止、监听状态、请求标识、上传确认、字节数、文件保存与连接失败。访问码和会话凭据不写入日志。

## 验证与交付

自动测试覆盖路径越界、同名文件处理、中文文件名、访问码失效、确认前拒绝正文、拒绝上传、分块收发、断开清理和连续两批上传。

在浏览器验证真实服务：多文件拖拽、目录导航、新建文件夹、下载内容一致、空文件、大文件、错误提示及刷新页面。iOS 编译由 macOS 执行；真机验证锁屏/后台后关闭与再次开启，以及现有 Windows 客户端互传不回归。

不把静态网页展示、Windows 测试通过或提交构建当作 iPhone HTTP 服务验证通过。GitHub 正在构建时按项目规则不轮询等待出包。

## 播放器本地音乐扫描

“从文件导入”继续由用户在“文件”App 中手动选择任意位置。“读取设备音乐资料库”执行一次自动扫描：读取系统音乐库、爱乐互传共享音乐目录，以及用户此前明确授权并保存访问权限的音乐文件夹。没有授权或已失效的目录跳过并汇总提示，不影响其他来源的扫描。第三方播放器的私有沙盒不绕过系统权限；它们若通过“文件”App 暴露目录并获得授权，即可纳入后续自动扫描。

扫描结果在写入播放器曲库前去重。优先以规范化的歌曲名、歌手、专辑和时长组成身份；元数据不足或不可靠时使用文件内容 SHA-256。相同歌曲来自多个来源时只建立一个曲库条目，来源优先级为系统音乐库、爱乐互传目录、用户授权目录；同名但歌手、专辑或时长不同的歌曲分别保留。曲库条目可保留多个来源位置，播放时优先使用当前可访问且可播放的来源。
